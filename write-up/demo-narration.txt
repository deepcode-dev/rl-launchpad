This is a from-scratch PPO agent for command-conditioned Unitree Go1 locomotion in MuJoCo Playground.

The policy receives a five-frame history of the stock forty-eight-value observation and produces twelve normalized joint targets. The actor and critic are separate two-layer neural networks. Actions come from a tanh-squashed Gaussian, and observation statistics are stored with each checkpoint.

The first version looked like it was training, but its live behavior was awful. The cause was not Gymnasium. I had flattened vector rollouts before generalized advantage estimation, so returns crossed between different robots. Fallen environments never reset. The wrapper reconstructed a different reward, and the Gaussian policy sent unbounded actions. I also removed an early synthetic benchmark chart that was not measured evidence.

The corrected contract keeps rollouts shaped by time and environment, distinguishes termination from time-limit truncation, bootstraps the real terminal observation, autoresets each finished slot, uses the native reward unchanged, and bounds every action. Fourteen regression tests cover these boundaries.

I trained seeds ten, eleven, and twenty-one for three hundred twenty-seven thousand six hundred eighty steps each. A longer run degraded on a validation block, so I archived it, early-stopped, and moved final evaluation to fifty untouched episodes starting at seed twenty thousand.

Custom PPO achieved a mean native return of ten point nine one, with mean episode length seven hundred forty-six. The matched Stable-Baselines3 baseline scored one point three one and two hundred eighty-two steps. SB3 uses the same vector batch, rollout size, observations, actions, reward, budget, and evaluation episodes; it is baseline only.

The main limitation is deployment realism. Windows ran MJX on CPU while PyTorch used an RTX thirty seventy, and viewer mouse pushes do not affect policy physics. The full return and episode-length distributions remain in the submitted JSON rather than hiding early falls.
